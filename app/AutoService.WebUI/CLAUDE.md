## Core Rules

- React + TypeScript + Tailwind only.
- i18n for all user text (EN + HU).
- No hardcoded `VITE_API_URL` fallback.
- Production builds need `VITE_API_URL`: `vite.config.ts` injects a build-only Content-Security-Policy meta tag whose `connect-src` and `img-src` carry the API origin (profile pictures load as `<img>` straight from the API). `style-src` is `'self'` for elements and attributes alike (no `style-src-attr` directive): no inline `<style>` element or `style` attribute remains - LoadingPage's styles live in `src/styles/loadingPageAnimations.css`, and any remaining runtime pixel value written through the CSSOM (`element.style`) is not governed by the CSP. Never add a React `style` prop or `style="..."` markup. `script-src` carries a `sha256-` hash per inline script, computed from the built `index.html`: today only the one that, on every route, applies the resolved theme before the first paint (saved `preferred-theme`, else `prefers-color-scheme`, the rule of `store/theme.store.ts`) and preloads `/AppLogoFrameWhite.webp` in the dark theme, and on `/login` reveals `#login-shell`, the static pre-React copy of the LoadingPage splash's first frame (mobile LCP). LoadingPage removes that copy in a layout effect on its first commit (`src/utils/loginShell.ts`); keep its markup in step with `LoadingPage.tsx`. `base-uri` is `'none'` (no `<base>` element is ever written), `manifest-src` is `'self'`, `upgrade-insecure-requests` is on, and Trusted Types are enforced (`require-trusted-types-for 'script'; trusted-types 'none'`): no code may create a Trusted Types policy or pass a string to a DOM injection sink (`innerHTML`, `dangerouslySetInnerHTML`, `eval`, `new Function`). Vendor chunks use Rolldown `codeSplitting` groups (`vendor-react`, `vendor-i18n`, `vendor-ui`, `vendor-query` for the four TanStack Query packages) with `strictExecutionOrder`; do not go back to `manualChunks`, which produced a circular chunk import and a blank built app.
- Two build-only plugins in `vite.config.ts` (never active in dev): `arsm-bundle-budget` warns, and never fails the build, when a JS chunk's gzip size exceeds `CHUNK_GZIP_BUDGET_BYTES` (today's largest chunk, vendor-react, rounded up to the next 10 kB); `arsm-precompress` writes a level-9 `.gz` sibling next to every emitted text asset of 1 kB or more for nginx `gzip_static`. There is no brotli step: the `nginxinc/nginx-unprivileged` image has no `ngx_brotli` module.
- Vite dev server binds to `localhost` by default; use `VITE_DEV_HOST` only for explicit local opt-in.
- Keep API logic in `src/services`; keep UI logic in components/hooks/pages.
- CSRF double-submit: `src/services/http/csrf-token.ts` reads the non-HttpOnly `__Host-autoservice_csrf` cookie, and the api client echoes it as the `X-CSRF-Token` header on every unsafe (non-GET/HEAD/OPTIONS) request.
- Private authenticated read models use TanStack Query. Keys are person/role-scoped. `clearAuth()` also clears the scheduler view key, the toast queue and the error-illustration Cache Storage. Reads are `queryOptions` factories in `src/services/queries` (`schedulerQueries`, `customersQueries`, `catalogQueries`, `quotesQueries`, `companyResultsQueries`, `profileQueries`, `adminQueries`) that take the scope of `useAuthQueryScope()` first. With no signed-in user the query is parked with `skipToken` under `SIGNED_OUT_QUERY_KEY`. A refetch of already cached data runs with `skipErrorRedirect`. `gcTime` and the persisted maxAge are 24 h. Only the `catalogQueries.partOptions` and `laborTypeOptions` queries, which hold no personal data, are persisted in sessionStorage by `startQueryCachePersistence` (`src/services/cache/queryClient.ts`). Persistence uses a buster carrying the person id, restores only once the user is known, writes at most once per second (trailing), and never persists mutations. The Customers, Quotes, Scheduler, Settings profile and Admin roster reads toast through `hooks/useReadFailureToast.ts`: one toast when a read starts failing, silent while it keeps failing (and for a failure the cache kept from before the mount), re-armed only by a successful load or a new `readKey` (for example the viewed month).
- `services/http/api-url.ts` is the only reader of `VITE_API_URL`. The axios client times out after 30 s. HTTP 500/502/503/504 redirect to `/500` unless the request sets `skipErrorRedirect`; the read services take `options?: SilentRequestOptions` for this. `restoreAuth` keeps the session and the hint on a timeout, network error or 5xx and redirects to `/500`, whose reload retries. Without a session hint it only clears the private query cache, so the warmed error-illustration cache survives an anonymous boot.
- `utils/i18n.ts` exports `i18nReady` and `changeAppLanguage(language: AppLanguage)`. `main.tsx` renders only after `await i18nReady`; only the active locale chunk loads at start-up (dynamic import), there is no fallback language, and the language switch is async: `changeAppLanguage` loads the target bundle, switches and persists `preferred-language` through `safeStorage`.
- Counted texts carry a base key plus `_one`/`_other` variants (the HU variants are identical, because Hungarian does not inflect after numerals). Call sites must pass a numeric `count`: i18next skips plural resolution when `count` is a string, and the variants format the number themselves with `{{count, number}}`.
- EN follows en-GB spelling (for example Labour types) and the HU quote concept is Árajánlat.
- Clean-design rule: no shadows (`shadow-*`, `dark:shadow-*`, `ring-*`, `ring-offset-*`, CSS `box-shadow`, `transition-shadow`); Tailwind rings render as `box-shadow`, so focus and selected states use `outline-*` or a border instead.
- Item surfaces (cards, panels, modals, sidebar sections) use one solid background token and no gradient overlay (user decision, 2026-09-28); only page-level backdrops (body, auth, shell, error page, loading splash) and the calendar scroll fade keep gradients.
- Style-system work is visual-preserving by default. Do not change current colors, spacing, radii, motion, focus, layout, or responsive behavior unless the user explicitly requests a redesign.

## Current UI Contract Anchors

- Customer search includes customer fields and related vehicle plates.
- Customer/vehicle history uses details panel or split-view flow.
- The Customers reads (list, a customer's vehicles, customer and vehicle repair history) are `useQuery` calls on the `customersQueries` factories, mounted where they render: vehicles and customer history only while the card is expanded, vehicle history only while its vehicle is selected. The list and the vehicles are paged queries (`customersQueries.listPage` and `vehiclesPage`) with `Pagination` controls (`customers-pagination-*`, `customer-vehicles-pagination-*`); the list page size comes from `useFittingPageSize`, the vehicles page size is fixed at 5, and there is no customers sort toggle because the API takes no `sortDirection` (always ascending). History direction is a local reverse of the server-ascending list. A failed read with no cached data toasts through the shared `hooks/useReadFailureToast.ts`: one toast per failure episode, re-armed by a successful load.
- The Customers, Inventory and Quotes lists fetch with the page size measured before the first request: `useFittingPageSize` returns `null` until its synchronous layout-effect measurement, the list query is `enabled: pageSize !== null`, so each page entry sends one request, and a blank search is omitted from the params (`services/http/page-params.ts`). The hook measures a rendered sample row plus the row gap, else the list's `estimateItemHeightPx(list)` (a full row pitch, chosen by list width: Inventory 69 px table, 193/192 px tile; Quotes 69 px table, 229/245 px tile; Customers 90/146/180/202 px from the width breakpoints of `estimateCardPitch`), else the fallback height plus gap. An unmeasurable list (not mounted, height 0) falls back to the minimum page size, so a list never stays unloaded. The estimates, the Customers reserved-bottom values (136/162 px) and its `639.98px` query mirror the card and pagination markup and Tailwind's `sm` breakpoint; re-check them in the 320px validation when that markup changes. The vehicles and mechanics lists keep a fixed size of 5.
- Customer and vehicle create/update/delete are `useMutation` calls whose `onSuccess` refreshes the touched keys and resolves after the mounted reads refetched, so a modal closes on fresh data. The keys are the list, the customer's vehicles, the affected histories, and the scheduler root after vehicle update/delete and customer delete, plus the quotes and company-results roots after a vehicle or customer delete (the API deletes a vehicle's quotes with it). The refreshers live in `pages/Customers/hooks/useCustomersListMutations.ts`.
- The customer and vehicle forms show a field's server or numeric validation message under the field (`FieldErrorText`), bound with `fieldErrorA11yProps` and an id from `useId()`. The error is pinned to the value it was raised for, so editing the field clears it, and the toast stays.
- The customer expander (`customer-expand-<id>`) carries `aria-expanded` and `aria-controls` pointing at the details region.
- The customer search field uses `filterNameSearchInput` (spaces and apostrophes allowed, digits still dropped); the create/edit forms keep `filterNameInput`.
- Repair history and appointment dates render through `formatShortDateTime`; the mileage through `formatQuantity`.
- Scheduler intake supports email, exact plate, and name multi-result lookup.
- Scheduler and customer reads keep query-cache stale times, visible-tab background refresh, and mutation invalidation behavior aligned with `src/services/cache`.
- Live update channels are built with `createLiveUpdateChannel` (`src/services/live`), which owns the SSE connection lifecycle, reference counting, auth-aware reconnect and logout teardown. A channel only supplies its URL, SSE event name, DOM event name and payload parser; do not hand-roll a second EventSource. The stream reconnects with exponential backoff and jitter (nominal 2 s doubling to 30 s, reset when a stream opens). The session is refreshed first only when the browser closed the stream (the server rejected it), never for a dropped or unreachable stream.
- The scheduler subscribes to `/api/appointments/updates` while mounted and refreshes the current view on each event, rather than patching local state, because an appointment can move between months.
- The scheduler lists come from `useQuery` reads in `useSchedulerDataSync` (visible-tab `refetchInterval`, invalidation on SSE and profile-picture events), `scheduler.store` keeps only the viewed month and selected day (`clearSchedulerSession()` resets it at logout), appointment actions are `useMutation` hooks in `useSchedulerActions` that write through `appointmentQueryCache`, and the intake customer lookup keeps a request-id guard because it is a debounced user-typed search of personal data, not a cacheable read.
- Profile picture upload accepts JPEG/PNG/WebP up to 4 MB (`MAX_PROFILE_PICTURE_BYTES`); the size check runs on both the selected file and the cropped blob, because cropping re-encodes and changes the size that is actually sent. Before anything is decoded, `utils/imageInspection.ts` checks the extension and MIME type (`hasAllowedPictureType`) and then the file head (`findPictureRejection`): the magic bytes and the pixel size from the PNG IHDR, JPEG SOF or WebP VP8/VP8L/VP8X header, refusing more than `MAX_PICTURE_SIDE_PX` (8192) per side or `MAX_PICTURE_MEGAPIXELS` (25) in area (`toast.pictureInvalidType` / `toast.pictureDimensionsTooLarge`).
- The crop modal produces `image/webp` at quality 0.9 with a `.webp` file name (`src/utils/imageCrop.ts`); the API re-encodes to WebP again server-side.
- Login validates on submit: the submit button is disabled only while a request runs; an empty field gets an inline `common.validation.fieldRequired`, a malformed identifier an inline message plus its toast, and the first invalid field takes focus (messages are flushed with `flushSync` first). The email/phone mode switch sits above the fields. `libphonenumber-js` is imported dynamically (`login.helpers.ts`) when phone mode is chosen or at a phone-mode submit, never statically.
- The Settings profile and the admin mechanic roster are `profileQueries.me` / `adminQueries.mechanics` queries; the roster is a fixed 5-row server-paged list (`mechanics-pagination-*`) with search and no ascending/descending toggle. Profile edits are a draft laid over the cached profile (`pages/Settings/profileFields.ts`), never a copy of it. Profile update, picture upload/removal, mechanic registration and mechanic delete are `useMutation` and write or invalidate those keys (`pages/Settings/hooks/useProfileCache.ts`, `useRegisterMechanicForm.ts`, `useMechanicListState.ts`); the picture-updated DOM event is still emitted for the sidebar.
- Parts and labor types live on `/inventory`: two tabs (Parts, Labor types) reflected in the URL (`?tab=parts` / `?tab=labor-types`), rendered by one generic `CatalogTab` (`pages/Inventory/components/CatalogTab.tsx`, configured by `catalogTab.config.ts`) sharing one generic `CatalogFormModal` (`components/CatalogFormModal.tsx`, configured by `catalogForm.config.ts`, one `CatalogFormState` for both kinds) and the delete modal, instead of separate Parts/Labor types tab and form components. Create/update/delete state and mutations are one generic `useCatalogItemMutations` hook, instantiated once per kind with its `catalogItem.config.ts` entry (server calls, cache key, toast and error keys). Both tabs are server-paged and server-searched (`useFittingPageSize`, `Pagination`, `HighlightedText`) with no sort toggle (always ascending); the VAT choices are 5, 18 and 27 (shared `Dropdown`, size `field`). Every gross value shown in a list row comes from the server DTO (`grossUnitPrice` / `grossHourlyRate`); the one client-side gross computation in the whole pricing vertical is the create/edit live preview (`computeLiveGrossPreview` in `pages/Inventory/helpers.ts`), which mirrors `Pricing/PricingCalculator.GrossUnitPrice` exactly.
- Quotes live on `/quotes`: the list is server-paged (`useFittingPageSize`, `quotes-pagination-*`), searched (quote number, title, plate; debounced about 300 ms) and status-filtered. The chips map to server filters (`toQuoteListFilter` in `pages/Quotes/helpers.ts`): `Expired` sends `expired=true`, `Sent` sends `status=Sent&expired=false`, so every page and the total count are exact and no row is narrowed client-side. Every row renders all three actions (open, download, delete); a non-draft row's delete button stays present but is natively `disabled`, with its title switching to `quotes.deleteDraftOnlyHint`, because only a draft can be deleted.
- A quote is anchored to a vehicle, so creation starts from the vehicle row on the Customers page (`FilePlus`, accent tone, outside the fixed Eye/Pencil/Trash semantics) and navigates to `/quotes?vehicleId=<id>&new=1`; the Quotes page consumes those parameters once and opens the create modal.
- `QuoteEditorModal` is split into `.header`, `.lines`, `.totals` and `.footer` files, and its body scrolls inside the dialog (`max-h-[60vh]`), because a document-sized modal otherwise pushes its footer actions off screen.
- The `.lines` section renders through `QuoteLineForm` (the inline add/edit editor) and `QuoteLineRow` (the saved-line display row); `resolveLineLabelKeys` and `applyCatalogSelection` live in `pages/Quotes/helpers.ts` so the add flow and the row share one source. Once the quote can no longer be edited, the actions column is omitted entirely, from the header down, rather than rendered disabled.
- Editor affordances follow the quote status: a draft is fully editable, a sent quote keeps its fields visible but disabled with a notice and only accepts a validity extension, and a decided quote is read-only. The appointment link is set at creation only, because the header update contract does not carry it.
- Every amount rendered on a saved line or in the totals comes from the server DTO. The only client-side computation is the live line preview in `pages/Quotes/helpers.ts`, which mirrors the server formula.
- The quote line editor relabels itself by line kind: a part is counted in pieces at a net unit price, labor in hours at a net hourly rate.
- The Quotes reads (the list, a quote's detail, the part and labor-type pickers, and the vehicle's repair history) are `useQuery` calls on the `quotesQueries`, `catalogQueries` (`partOptions`, `laborTypeOptions`) and `customersQueries` factories. A quote write puts the returned quote into the detail cache and prefix-invalidates `quotes.list` instead of patching a row; a delete removes the detail. Selects are the shared `Dropdown` (the header appointment select uses size `field`); VAT options are 5, 18 and 27, and a saved legacy 0 line still renders but its VAT dropdown shows the placeholder until a valid rate is picked. Create, validity extension, status change and delete mark the `queryKeys.companyResults` root stale. Quote writes use `networkMode: 'always'` and fail fast while offline instead of pausing. The editor header title and the line form's quantity, description and net price show a bound inline error (`fieldErrorA11yProps` plus `useId`) after a failed save attempt, in addition to the existing toast.
- Company results live on `/company-results`: a year plus an optional month, the accepted net and gross as the headline, and the pending, expired and rejected amounts beside them at a lower weight. Every figure comes from the server DTO through `formatHuf`, so the page shows whole forints and never derives an amount. Charts are deliberately out of scope. The month and VAT breakdowns are `DataList`s: a column table once the list is wide enough, otherwise compact rows under a visible header strip (`MobileColumnStrip`). Both lists lay their value cells out with `mobileValuesClass` (`mobileColumns.ts`), and `MobileStackedValues` renders the stacked value cells, so below 360px each value gets its own labelled line, because three amounts do not fit one line there. In `CompanyResultSummary` no financial figure is ever ellipsized (`[overflow-wrap:anywhere]`, headline `text-xl sm:text-2xl`).
- Settings has an Admin-only "Company data" section (`sections/CompanyDataSection.tsx`, state in `useCompanyProfileSettings`, data via `adminQueries.companyProfile`, `GET`/`PUT /api/admin/company-profile`). Field length caps in `companyProfileFields.ts` mirror the backend `CompanyProfileLimits` (name 150, addressLine 150, city 50, postalCode 4, taxNumber 13, phone 20, email 150).
- The quote PDF is downloaded through `quoteService.downloadPdf` (blob response, file name taken from `Content-Disposition`) and handed to the browser by `saveBlobAsFile`, which revokes the object URL right after the click. The action sits both on the list row and in the editor footer, and it is offered in every status, because every status is printable.
- `utils/currency.ts` exports two formatters, never a value the server did not already compute: `formatHuf` for whole-forint amounts (line/total amounts, report totals) and `formatHufUnitPrice` for a unit price or hourly rate with exactly 2 decimals.
- `utils/number.ts` exports `formatQuantity(value, locale)` for locale-aware quantities and counts (line quantities/hours, quote/month counts); it only formats and never rounds or derives a value the caller did not already have. Money still goes only through `formatHuf` / `formatHufUnitPrice`.
- `utils/currency.ts` and `utils/number.ts` format through the memoized `getNumberFormat` of `utils/intlFormat.ts`. That module is the only place that builds `Intl` objects: `toIntlLocale` maps `hu` to `hu-HU` and `en` to `en-GB`, `getDateTimeFormat` / `getNumberFormat` memoize per locale and options, and the canonical 24-hour date presets (`formatShortDate`, `formatShortDateTime`, `formatTime`, `formatLongDate`, `formatLongDateTime`, `formatMonthYear`, `formatMonthName`, `formatWeekdayShort`, each `(value: Date | string, language)`) are what pages use; an unparsable date renders `-`. Feature code never calls `new Intl.DateTimeFormat` or `toLocaleString`.
- Browser storage goes through `utils/safeStorage.ts` (`readStorage` / `writeStorage` / `removeStorage` with `'local' | 'session'`), which never throws in privacy mode or on a full quota. Errors are logged through `utils/devLog.ts` `logError(context, error)`: DEV prints the whole error, production only `[context] <error name>`.
- A validated field is bound to its visible error text with `fieldErrorA11yProps(errorId, error)` from `utils/fieldA11y.ts` (`aria-invalid` plus `aria-describedby`); the error element carries the same `id`, taken from `useId()`. Login, Settings, Admin registration, Customers, the Inventory catalog form and the Quotes editor all render the shared `components/common/FieldErrorText` under the field; Settings and Admin registration show a server or submit-time message only when it is a `common.validation.*` key (Settings also `settings.errors.*`), and generic failure keys stay toast-only. The Settings password form keeps its disabled-reason hint under the button as the error text of the too-short and mismatch cases and binds the offending field to it.
- Name inputs: `filterNameInput` (Unicode letters and hyphen, matching the backend `NamePattern`) stays on every create/edit form; `filterNameSearchInput` (also spaces and the apostrophes `'` and U+2019) is for name search/filter fields only. Both live in `utils/validation.ts`.
- The pricing vertical's locale strings live in their own pair, `utils/locales/{en,hu}.pricing.ts`, merged into `en.ts`/`hu.ts` alongside the existing `.core.ts`/`.feature.ts` split, with the same EN/HU key-for-key parity discipline.
- A text shown in more than one place with the same EN and HU wording exists once: under `common.*` (`actions`, `sort`, `fields`, `placeholders`, `validation`) in `utils/locales/{en,hu}.core.ts` when several features use it, otherwise on the one existing key of its own namespace. Do not add a second key for an existing text. EN labels, titles and buttons use sentence case. Server validation messages map to `common.validation.*` for both the admin and the settings context (`utils/serverValidation.ts`).
- Routes: `src/router/appRoutes.ts` (`APP_ROUTE_PATHS`) is the one route table; `App.tsx`, the route guards, the sidebar nav, `SeoManager` and the splash (`isSplashRoute`) all read it, so add a route there first.
- Splash: `LoadingPage` shows on a full load of every route of that table except `/500`, stays until the session restore has finished and i18n is ready, for at least `FIRST_LOAD_SPLASH_MIN_VISIBLE_MS` (2500 ms) on the very first full load in this browser (localStorage flag `arsm-splash-shown`, via safeStorage; later loads and new tabs keep only the short minimum) and `SPLASH_MIN_VISIBLE_MS` (250 ms) afterwards, and never returns once dismissed. It has no reduced-motion rule (a past regression). The lazy-route Suspense fallback is the centered `role=status` spinner (`centeredLoadingWrapperClass`); `NotFound` is imported eagerly, so the 404 route shows no Suspense spinner.
- Theme: the store follows `prefers-color-scheme` and its changes until the user picks a theme (`hasChosenTheme`); the saved `preferred-theme` then wins. The theme toggle renders lucide Moon/Sun for the active theme; the language toggle shows the language it switches to (EN while Hungarian is active).
- `index.html` and `site.webmanifest` declare `lang` hu (the default language); `SeoManager` syncs `html[lang]` at runtime.
- `ToastViewport` keeps one persistent `<output aria-live="polite" aria-atomic="false">` mounted (empty without toasts) that holds every toast row, so each added toast is announced; an error row's message carries `role="alert"`. Text wraps; error toasts last 10 s, the others 5 s (`store/toast.store.ts`); hovering (mouse or pen) or focusing a row pauses its countdown, which resumes with the remaining time. `clearToasts()` (exported by `store/toast.store.ts`, called by `clearAuth`) empties the queue, and the rows' timers stop with them.

## Current Style Contract Anchors

- Canonical style sources: `src/utils/styles/{buttonStyles,fieldStyles,surfaceStyles,textStyles,toneStyles}.ts`, `src/utils/formStyles.ts`, `src/styles/tokens.css`.
- Extract only the repeated minimum common subset: geometry, base layout, radius, focus, motion, disabled state, typography, and reusable responsive wrappers.
- Colors come from the shared semantic tones in `utils/styles/toneStyles.ts` (`toneBadgeClasses`, `toneDotClasses`, `toneFeedbackClasses`, `toneTextClasses`, `toneFilterChipClasses`). A feature only maps its own states to a tone (`APPOINTMENT_STATUS_TONE` in `pages/Scheduler/utils/appointmentStatusTone.ts`, `QUOTE_STATUS_TONE` in `QuoteStatusBadge.tsx`) and never re-types palette classes.
- Keep feature-specific state, placement, spacing, and rare variants local in the owning TS/TSX file or feature module.
- Dark mode is a CSS-variable swap: `styles/tokens.css` declares `ui-*` semantic colours that resolve through `--ui-*` variables swapped under `.dark`. A matching light/dark pair is written once as `P-ui-X`, a mismatched pair keeps its explicit `dark:` class, and the static `arsm-*` palette stays defined.
- `focusVisibleOutlineClass` (`utils/styles/surfaceStyles.ts`) is the only keyboard focus style (form fields add the `ui-focus` border): a 2px outline at 2px offset in `ui-focus` (#6e53ad light, #a98fe0 dark), with `arsm-focus-outline` in `components.css` as its resting colour. Non-focus selected and active states use `outline-1` or `outline-2`, never a ring. The Scheduler `AppointmentCard`'s full-card overlay button is the one exception and uses an inset variant (`focus-visible:-outline-offset-2`, the local `overlayFocusOutlineClass` in `pages/Scheduler/components/shared/AppointmentCard.tsx`), because the card's `overflow-hidden` would clip an outer outline; every other control keeps the 2px offset.
- Form fields use `border-ui-field-border` (#8b7cc0, 3:1); cards and panels keep `ui-border`. On focus a field's border switches to `ui-focus` (`focus-visible:border-ui-focus` in `textFieldSurfaceClass`, `compactSelectClass`, `filterSelectCompactClass` and `readonlyInputClass`), so focus stays visible under an `overflow-hidden` wrapper that clips the outline. The neutral compact chips (`compactChipNeutralToneClass`) use `border-ui-field-border` too, like the filter selects beside them, and `.crop-zoom-slider` has its own `:focus-visible` 2px outline at 2px offset (`components.css`). `toneBadgeClasses` uses `arsm-badge-success-text` / `arsm-badge-error-text` for the light badge text.
- The radius and type scales: `rounded-ui-xs|sm|md|lg|xl|pill` and `text-ui-micro|caption|small|field|body|title|heading|display`, with 11 px (`text-ui-micro`) as the floor. ProfilePictureSection keeps a 3 px decorative halo (`outline-3`), which is not a selected/active state.
- Inter is self-hosted in `public/fonts/` (two woff2 files plus `OFL.txt`, `@font-face` in `styles/base.css`, `font-display: swap`); ő and ű come from the latin-ext file.
- Aligned lists (Quotes, quote lines, Inventory parts/labor types, Company results months and VAT rows) share one set of primitives in `src/components/common/DataList.tsx`: `DataList` (the root), `DataListRow` (`lead`, the value cells, `actions`), `DataListCell`, `DataListText` and `DataListFullRow`. Every row and cell renders once, with no desktop/mobile twin: the list root is one CSS grid, and the header and every row share it via `grid-cols-subgrid`, so columns cannot drift with text/number length or icon count; the tile layout is the same row as a two-track grid, the header line (lead plus actions) over the value tiles. The tile/table switch is a container query on the list's own width (`dataListBreakpointClasses` and the text roles in `src/components/common/dataListLayout.ts`; `lg` | `3xl` | `4xl`), not a viewport breakpoint, because the collapsible sidebar changes the available width. A `ResizeObserver` (`useDataListLayout`) only mirrors the container query to swap the ARIA roles: `table`/`row`/`columnheader`/`cell` in the table layout, `list`/`listitem` in the tile layout. Test hooks: `data-list-header` (displayed in the table layout only), `data-list-cell` with `data-column`, and `data-list-cell-label` (tile layout only). `DataList`'s own loading spinner (`role="status"`) and dashed empty-state box (`emptyStateBoxClass`) follow the same pattern the Customers list already used. Only the column grid template (for example `quoteColumnsClass` in `QuoteList.tsx`, `catalogColumnsClass` in `Inventory/components/CatalogTab.tsx`) stays a feature-local literal applied once at the list root; the subgrid/container-query mechanics live in the shared component, not per feature.

## Validation Policy

- Frontend security remediation (`npm audit fix`, then `npm audit signatures`) runs in the `scripts/validate.py` security stage when `package.json` or `package-lock.json` changes.
- `.npmrc` sets `min-release-age=7` and `ignore-scripts=true`: npm resolves only versions published at least 7 days ago, so `npm audit fix` cannot install a fix younger than 7 days, and no dependency lifecycle script runs (native binaries ship as optionalDependencies).
- Validate with `python scripts/validate.py` (runs `npx tsc -b --noEmit` and eslint on the changed files), and `npm run build` when needed. Plain `tsc --noEmit` type-checks nothing here, because the root `tsconfig.json` is solution-style (`files: []` + `references`); only build mode (`-b`) walks the referenced projects.
- TypeScript 7 runs side by side with the TypeScript 6 API (Microsoft's documented setup): `"typescript": "npm:@typescript/typescript6@^6.0.2"` keeps the JavaScript API that `typescript-eslint` needs for type-aware `strictTypeChecked`, and `"@typescript/native": "npm:typescript@^7.0.2"` provides the `tsc` 7.0.2 that `npm run build`, `npx tsc -b` and `scripts/validate.py` run. Check it with `npx tsc --version`.
- Both TypeScript packages ship a `tsc` bin (the TS 6 one through the hoisted `@typescript/old`). A clean `npm ci` (CI, Docker) links `tsc` to `@typescript/native`, but an incremental `npm install` can leave `node_modules/.bin/tsc` on TS 6: delete `node_modules/.bin/tsc*` and run `npm rebuild @typescript/native`. Swap the alias with `npm install -D typescript@npm:@typescript/typescript6`, because a plain `npm install` keeps an installed `typescript` that merely satisfies the version range.
- eslint runs `typescript-eslint` `strictTypeChecked` (type-aware through `projectService`, which resolves each file to its project via the solution-style `tsconfig.json`), `eslint-plugin-jsx-a11y` and the `react-hooks` recommended preset with `set-state-in-effect` on.
- `tsconfig.app.json` and `tsconfig.e2e.json` set `noUncheckedIndexedAccess` (an indexed read is `T | undefined`) and `exactOptionalPropertyTypes` (an optional property rejects an explicit `undefined`).
- `package.json` `overrides` points the ESLint peer of `eslint-plugin-jsx-a11y` at the project's own `eslint` (`"$eslint"`), because the plugin declares no ESLint 10 peer range.
- The React Compiler runs through Babel (`babel({ presets: [reactCompilerPreset()] })` from `@rolldown/plugin-babel` in `vite.config.ts`). `@babel/core` stays on 7.x, because with Babel 8 the compiler bails out on destructured defaults.
- Routing imports come from `react-router`; `react-router-dom` is removed.
- Style refactors need before/after visual preservation evidence for affected surfaces, including 320px when layout can wrap.
- E2E only on gate: `python scripts/run-local-test-suite.py playwright` and inspect sanitized report.
