## Auth and Runtime Anchors

- Cookies: `__Host-autoservice_at` (10 min), `__Host-autoservice_rt` (7 days), `__Host-autoservice_csrf` (double-submit CSRF token, `HttpOnly=false` so script can read it, same 7-day lifetime as `__Host-autoservice_rt`) - `Auth/Session/CsrfTokenCookie` issues/rotates it on successful login, refresh and password change, and clears it on logout and profile deletion, alongside `__Host-autoservice_at`/`__Host-autoservice_rt`. The `__Host-` prefix needs `Secure`, `Path=/` and no `Domain`, on every issue and on every deletion: a deletion without `Secure` is ignored by the browser, so `ClearSessionCookies` and `CsrfTokenCookie.Clear` repeat `Secure`, `Path=/` and `SameSite=Strict`. Sessions that still carry the old unprefixed names are not migrated (one-time re-login).
- Unsafe cookie-bearing API mutations require an allowed WebUI `Origin` header (`UnsafeCookieRequestOriginMiddleware`) and, running immediately after it, a matching `X-CSRF-Token` header equal to the `__Host-autoservice_csrf` cookie (`Middleware/CsrfDoubleSubmitMiddleware`, compared with `CryptographicOperations.FixedTimeEquals`) on every unsafe `/api` request except `POST /api/auth/login`; a missing or mismatched header is `403 csrf_token_invalid`. Both middlewares share request classification via `Middleware/UnsafeCookieRequestClassifier`.
- Rate limits (`Security/RateLimitPolicies`, fixed one-minute windows): login `10/min` and refresh `20/min` per client address; `POST /api/profile/change-password` and `DELETE /api/profile` `5/min` and `PUT /api/profile/picture` `10/min` per signed-in person (Development raises every limit except refresh to `300/min` for the local test suite). The limiter runs after `UseAuthorization`, because the per-person partitions read the validated principal. Lockout after 5 failed password checks for 15 min: `Auth/Security/PasswordCheck` is the one verification (`CheckPasswordSignInAsync(lockoutOnFailure: true)`) of login, change-password and profile deletion, and a locked-out account answers the same 429 `lockout_active` body on all three.
- In-process auth rate limits/login bans, the warmed token denylist and the session cutoffs are single-instance only; non-Development deployments must explicitly confirm `Deployment:RateLimiterTopology=SingleInstance` or use a distributed limiter. The cutoffs live in memory only, so a restart forgets them and a revoked access token then lives until its own expiry (at most 10 minutes; the refresh tokens stay revoked in the database).
- Access-token revocation is checked in memory (`Auth/Security/AccessTokenValidation`, the `OnTokenValidated` event): `TokenDenylistService` warms the live `revokedjwttokens` rows at startup (hosted service) and only queries the table while the warm-up failed; `Security/SessionRevocationService` keeps a per-person "tokens issued before X are invalid" cutoff (whole seconds like the `iat` claim, climbing with every revocation; `JwtTokenIssuer` dates a new token at the cutoff when that is ahead of now, so the replacement issued right after a revocation survives it) and closes the person's SSE streams through `Realtime/IUserSubscriptions`. `RevokeAll` runs on an admin mechanic delete, an admin password reset, a self password change (every other session) and a self profile delete.
- Refresh (`AuthEndpoints.Refresh`): a rotated token replayed within `RefreshReuseGrace` (30 s) while its successor is still active answers 204 and rotates nothing (the same browser's parallel request); after that window, or with the successor gone, the reuse revokes the descendant chain (401). A locked-out identity cannot refresh (401). The refresh token stays bound to the client address hash issued with it (an owner decision kept as it was). `ExpiredTokenCleanupService` deletes every expired refresh row hourly, revoked or not.
- Admin password reset: `POST /api/admin/mechanics/{id}/password-reset` (`AdminEndpoints.PasswordReset`, `AdminOnly`, body `temporaryPassword`) resets the password through Identity's reset token (`AddDefaultTokenProviders`), sets `Mechanic.MustChangePassword`, revokes the refresh tokens and the sessions and logs the actor; 403 for the caller's own id or an admin target, 404 unknown, 400 for a blank or policy-breaking password. The access token then carries `pwd_change_required` (`PasswordChangeRequiredClaim`) and `Middleware/PasswordChangeRequiredMiddleware` (after `UseAuthorization`) answers 403 `{"code":"password_change_required"}` to every `/api` request except change-password, logout, refresh and validate; `POST /api/profile/change-password` clears the flag and issues fresh tokens. Login and `GET /api/auth/validate` answer `SessionResponse` (`personId`, `isAdmin`, `mustChangePassword`).
- Profile picture GET responses keep private browser caching with ETag revalidation and auth/cookie-aware `Vary` headers; SSE update behavior remains intact.
- Live update channels share `Realtime/`: `UpdateBroadcaster<TEvent>` owns the bounded per-subscriber fan-out and the subscription caps, and `ServerSentEventStream` owns the SSE framing, keep-alive and idle timeout, plus the whole handler lifecycle (`ServeAsync`: subscribe, 503 at the cap, stream, always unsubscribe). Payloads serialize as camelCase, because the static `JsonSerializer` call does not pick up the ASP.NET Core JSON options and the browser parsers would drop PascalCased frames.
- `DELETE /api/appointments/{id}` is `AdminOnly` (404 `appointment_not_found` when missing); linked quotes keep existing because their FK is `SET NULL`. `DELETE /api/customers/{id}` and `DELETE /api/vehicles/{id}` are `AdminOnly` too (403 before the lookup), because their cascade deletes the appointments and quotes under them, Accepted ones included; both log an info line with the actor's person id.
- Optimistic concurrency is one rule (`Data/OptimisticConcurrency`, `IVersioned`): `Quote`, `Part`, `LaborType` and `Appointment` map `Version` onto Postgres `xmin` (`MapXminVersion`, no real column), every edit of them submits the version it read (`GetMissingVersionError`: 0 or missing is 422 `Version is required.`), and `SaveWithVersionAsync` answers 409 `{"code":"<entity>_version_conflict"}` (`quote_`, `part_`, `labor_type_`, `appointment_version_conflict`, the shared `Http/ErrorCodeResponse`) when it is stale. Covered edits: the part and labor type `PUT`, `PUT /api/appointments/{id}` and `PUT /api/appointments/{id}/status`; every appointment response carries the new version. Deletes and the appointment vehicle edit take no version.
- `people.PhoneNumber` carries the filtered unique index `IX_people_PhoneNumber` (`WHERE "PhoneNumber" IS NOT NULL`), because login resolves a phone with `FirstOrDefault`; the `AddPhoneIndexPasswordResetAndRowVersions` migration first nulls later duplicates (a mechanic keeps the number over a customer, the lowest id over a later row). The handlers keep their 400 pre-checks; `PUT /api/profile` maps the race the index decides to 409.
- `Program.cs` enables `EnableRetryOnFailure`, so every explicit transaction (register, profile update and delete, mechanic delete, unassign, intake) runs through `Data/TransactionalExecution.ExecuteInTransactionAsync`: the retriable unit clears the change tracker, loads what it writes and commits itself; returning without a commit rolls back.
- Kestrel caps every request body at 64 KB (`JsonRequestBodyLimitBytes`); the profile picture upload lifts it for its own route with `RequestSizeLimitAttribute` (4 MB + 64 KB). A bigger body answers 413 through the problem-details handler.
- Startup (`Data/DatabaseInitializer.EnsureDatabaseReadyAsync`) migrates, then, while no mechanic and no Identity account exists, clears the mechanic-less rows the 2026-04 BackfillDemoData migration inserts into every database (fresh ones included), checks that no appointment lacks a mechanic and normalizes persisted data (`DatabaseInitializer.Maintenance.cs`). It seeds nothing (user decision 2026-10-12; the `DemoData` section is gone): a fresh database holds no mechanics, customers, vehicles, appointments, parts, labor types or quotes, so the HTTP suite creates its own fixtures (`tests/API/_setup`).
- First-admin bootstrap (`Data/AdminBootstrapInitializer`, after `EnsureDatabaseReadyAsync`, every environment): only when `Bootstrap:Admin` is configured (`Email`, `Password`, `FirstName`, `LastName`, `Specialization`, `Expertise` array; optional `MiddleName`, `PhoneNumber`; env `Bootstrap__Admin__*`, `Bootstrap__Admin__Expertise__0`) and no user holds the Admin role (matched by normalized role name), it creates one confirmed Admin mechanic under the registration rules. The write runs in one transaction inside the EF execution strategy, holding the transaction-scoped advisory lock `pg_advisory_xact_lock(0x4152534D41444D31)` ("ARSMADM1"), and re-checks the admin and email/phone conflicts under that lock, so concurrent instances create at most one admin. Existing accounts are never touched; invalid config and any failure (DB errors included) are logged without secrets or exception messages, and startup always continues. Remove `Bootstrap__Admin__Password` once the admin exists.
- Every appointment mutation publishes `AppointmentUpdatedEvent` after its save, so `GET /api/appointments/updates` subscribers see other users' changes without polling. A handler that saves but does not publish is a bug.
- Read-only profile GET/person lookup paths use `AsNoTracking`; the profile mutations check on an untracked person and write through entities they load tracked inside their retriable unit (the profile delete deletes by id).
- Preserve middleware and endpoint mapping order in `Program.cs`; `UseForwardedHeaders` runs before `UseHsts` and `UseHttpsRedirection`, so behind a proxy they see the original https scheme; `PasswordChangeRequiredMiddleware` and `UseRateLimiter` run after `UseAuthentication`/`UseAuthorization`, because both read the validated principal.
- Six list endpoints are paged: `GET /api/customers`, `/api/customers/{customerId}/vehicles`, `/api/parts`, `/api/labor-types`, `/api/quotes` and `/api/admin/mechanics`. They take `page` (default 1, below 1 becomes 1), `pageSize` (default 20, clamped `1..500`, `ListQueryLimits.NormalizePage`) and, except the customer vehicles list, an optional `search` (`Pagination/SearchTerm.Normalize`: trimmed, max 100 chars, case-insensitive `ToUpper().Contains` substring match); none takes a `sortDirection`, and customers and mechanics always order ascending by last name, first name, id. They return `Pagination/PagedResult<T>` (`items`, `totalCount` over the whole filter, effective `page` and `pageSize`) via `ToPagedResultAsync` on an already ordered query; a page past the end returns empty `items` with the real `totalCount`. These six take no `limit`.
- The remaining unbounded lists (appointment history lists, `GET /api/vehicles/{vehicleId}/quotes`) keep the row cap `Pagination/ListQueryLimits.Normalize`: a client-supplied `limit` is clamped to `1..500`, defaulting to `500` when absent. `CustomerEndpoints.Lookup.cs`'s `NormalizeCustomerLookupLimit` keeps its own clamp for that one endpoint's different range.
- `SecurityHeadersMiddleware` appends `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy` and, outside the Development OpenAPI/Scalar routes, a restrictive `Content-Security-Policy`, on every response, plus `Cache-Control: no-store` on every `/api` response, without overwriting a header a downstream component already set (the picture GETs keep `private, max-age=3600`, the SSE streams `no-cache`).
- Client addresses never reach the logs or the database raw: `Security/ClientIpAddress.Hash` (a 12-character SHA-256 prefix) is the one helper behind the auth log lines, the access-denied audit line and the refresh-token binding.
- `JwtSettingsResolver.ResolveSecret` fails fast at startup if `JwtSettings:Secret` (env override `JwtSettings__Secret`) is missing, still carries a template placeholder marker, or is shorter than 32 bytes (the HMAC-SHA256 minimum).

## Profile Picture Storage Anchors

- `ObjectStorage:Provider` selects the backend: `S3` (default when unset; local RustFS, Cloudflare R2, AWS S3) or `AzureBlob` (`AzureBlobProfilePictureStorage`, `Azure.Storage.Blobs`; reads `ConnectionString`, `BucketName` as the container, `AutoCreateBucket`). Both share `ProfilePictureObjectKeys` and fail fast at startup when the bucket/container is missing and auto-create is off.
- Profile pictures live exclusively in object storage (`Storage/`: `IProfilePictureStorage`, `S3ProfilePictureStorage` via `AWSSDK.S3` or the Azure Blob implementation); the `people.ProfilePicture` bytea column was dropped and `People` keeps only `ProfilePictureObjectKey`, `ProfilePictureETag`, `ProfilePictureContentType`.
- `ObjectStorageSettingsResolver` resolves `ObjectStorage:*` settings, letting `ObjectStorage__*` environment variables win over config; it rejects blank values and template-placeholder markers and fails fast at startup.
- `ObjectStorageBucketInitializer` (hosted service) verifies the bucket at startup and creates it only when `ObjectStorage:AutoCreateBucket` is true.
- `ObjectStorage:DisablePayloadSigning` and `ObjectStorage:DisableDefaultChecksumValidation` are provider compatibility switches, not preferences. MinIO and RustFS (the local store since the MinIO images were withdrawn) want the AWSSDK.S3 defaults (`false`); Cloudflare R2 rejects the streaming SigV4 payload signing and the CRC32 checksum that AWSSDK.S3 v4 sends by default, so R2 needs both `true`. Keeping them in config is what makes a provider switch code-free.
- Uploads accept JPEG/PNG/WebP up to 4 MB (`MaxProfilePictureBytes`); the endpoint also enforces `MaxProfilePictureRequestBytes` (upload limit + 64 KB) via `RequestSizeLimitAttribute`/`RequestFormLimitsAttribute` so oversized bodies are rejected before buffering.
- `SkiaProfilePictureProcessor` (`Imaging/`, SkiaSharp) guards a 20-megapixel decode limit from the image header before decoding (the WebUI's `MAX_PICTURE_MEGAPIXELS` matches it), decodes at most two uploads at once (a static `SemaphoreSlim`, since one decode is 80 MB of pixels in a 1 GiB container), applies the EXIF orientation, resizes to fit 512x512 without upscaling, and re-encodes to lossy WebP (quality 80) with a SHA-256 ETag; stored objects are always WebP regardless of the accepted upload type. `SkiaSharp.NativeAssets.Linux.NoDependencies` supplies the native library for the Linux container (glibc and libstdc++ only, both in the `aspnet` runtime image).

## Catalog Anchors

- 10 endpoints under the `MechanicOnly` policy: 5 each on `/api/parts` and `/api/labor-types` (list, get, create, update, delete). Both run on `Catalog/CatalogItemHandlers` (Template Method: validation order, key normalization, paging and status codes); `Catalog/PartEndpoints*.cs` and `Catalog/LaborTypeEndpoints*.cs` keep the routes, the DTOs and a small subclass that names the key column and maps entity and DTO.
- `Domain/Part.cs` and `Domain/LaborType.cs`: a net price/rate (`numeric(18,2)`) plus an int `VatRatePercent` — not an enum, because it is a number multiplied into a price, not a behavioral category — restricted for new writes to `5`, `18`, `27` by `Validation/PricingValidation.GetVatRateValidationError` (Part/LaborType create and update, quote line snapshots; `0` is rejected with 422 `InvalidVatRate`). The named check constraints `CK_Parts_VatRate` and `CK_LaborTypes_VatRate` still allow `0`, so stored rows are untouched. `PartNumber`/`Code` carry a unique index.
- `PartDto.GrossUnitPrice` and `LaborTypeDto.GrossHourlyRate` come from `Pricing/PricingCalculator.GrossUnitPrice`, a **display-only** formula (`round(net * (1 + vat/100), 2)`) that never feeds quote line or total math — those always derive gross from addition (see Quote Anchors below). The WebUI's Inventory create/edit preview (`computeLiveGrossPreview`) is the one client-side place that mirrors this same formula.

## Quote Anchors

- 12 endpoints under the `MechanicOnly` policy (`Quotes/QuoteEndpoints.cs`): 10 on `/api/quotes` (list, get, update, delete, add/update/delete line, change status, extend valid-until, pdf) and 2 on `/api/vehicles/{vehicleId}/quotes` (list, create).
- `Domain/Quote.cs` and `Domain/QuoteLine.cs`: `QuoteStatus` (Draft, Sent, Accepted, Rejected) and `QuoteLineKind` (Part, Labor) are string-enum columns. `Expired` is a computed DTO flag (`Status == Sent && ValidUntil < now`), never a stored value; `GET /api/quotes` filters on the same rule with `expired=true|false` (false excludes expired quotes), so the paged counts stay exact.
- Status is a single allow-list, `QuoteEndpoints.StatusMutations.IsAllowedQuoteStatusTransition`: `Draft -> Sent -> Accepted` or `Rejected`; `Accepted`/`Rejected` are terminal. `Draft -> Sent` additionally requires at least one line. Every other transition, and every transition without at least one line when moving to `Sent`, is 409; `SentAt`/`DecidedAt` are stamped the same way `Appointment` stamps `CompletedAt`/`CanceledAt`.
- `Quotes/QuoteNumberGenerator` assigns `ARSM-{yyyy}-{0000}` on creation: a per-year, zero-padded sequence read from the highest existing number for that year, with a unique index on `QuoteNumber` as the real source of truth and up to 5 retries on a Postgres `23505` unique-violation race (`Data/UniqueConstraintDetection`).
- Optimistic concurrency: `Quote.Version` maps to the Postgres `xmin` system column through the shared `Data/OptimisticConcurrency` (see Auth and Runtime Anchors), not a real column. Every write mutation requires the client-submitted version; DELETE takes it as a `?version=` query parameter. A stale version returns 409 with body `{"code":"quote_version_conflict"}`; a missing (zero) version returns 422. `GET /api/quotes` and `GET /api/vehicles/{vehicleId}/quotes` project into `QuoteListItemDto` on the server (`QuoteListItemProjection`), so no People row is loaded for a list.
- `Validation/QuoteValidation.cs`: required title <= 120 chars, `ValidUntil` cannot be in the past, and a 200-line-per-quote cap enforced at the handler level (a per-row CHECK constraint cannot see sibling row counts). `CK_QuoteLines_LineKindIntegrity` plus a matching handler check enforce that a Part line carries no `LaborTypeId` and a Labor line carries no `PartId`. Quote line `Quantity`/`NetUnitPrice`/`VatRatePercent` reuse `Validation/PricingValidation` verbatim.
- Money rounding is one rule everywhere: `Pricing/MoneyRounding.RoundMoney` rounds to 2 decimals away from zero. `Pricing/QuoteLineCalculator` rounds `NetAmount` and `VatAmount` independently and then sets `GrossAmount = NetAmount + VatAmount` (addition, never a rounded multiplication); `Pricing/QuoteTotalsCalculator` sums line amounts into `TotalNet`/`TotalVat` and sets `TotalGross = TotalNet + TotalVat` the same way.
- Line and quote totals are stored, not computed on read: `Pricing/QuoteLineCalculator` and `Pricing/QuoteTotalsCalculator` are the only place amounts are computed, and `AutoServiceDbContext.ValidateQuoteTotals` throws on `SaveChanges`/`SaveChangesAsync` if a modified quote's stored totals disagree with its loaded lines, or if totals changed without loading `Lines`. The `CK_Quotes_Totals` check constraint (`TotalGross = TotalNet + TotalVat`) backs the same invariant at the database level.
- No quote is seeded: a fresh database holds none, and `QuoteNumber` is generated per creation. The HTTP suite addresses its anchor quote by its fixture title (`ARSM fixture anchor quote`, created by `tests/API/_setup/ensure-test-fixtures.http`), never by a number.
- `GET /api/quotes/{id}/pdf` renders the quote with QuestPDF and answers `application/pdf` named after the quote number; a missing quote is 404, never 500. Every status is printable, and the document prints its own status, expiry included.
- `Quotes/Pdf/` holds the render pipeline: `QuoteDocumentModel` (flat, no EF entity reaches the renderer), `QuoteDocument` (A4 portrait, 2 cm margins, repeating letterhead and page counter), `QuoteDocumentSections[.Lines]` (sections, with separate parts and labor blocks whose column labels differ), `QuoteDocumentFormatting` (hu-HU culture pinned, unit prices two decimals, line and total amounts whole forints) and `QuoteDocumentAssets` (embedded Noto Sans faces and the black logo).
- PDF runtime setup lives in the composition root: the QuestPDF Community license, `UseSystemFonts = false` and `ThrowOnMissingTextGlyphs = true`. A font without the Hungarian letters therefore fails the request instead of printing empty boxes on a customer's paper.
- The quote letterhead (D18) lives in the single-row `companyprofiles` table (`CompanyProfiles/CompanyProfileEntity`, id pinned to 1 by `CK_CompanyProfiles_SingleRow`); `GET /api/quotes/{id}/pdf` always reads the current row, with no per-quote snapshot. `Configuration/CompanyProfileResolver.cs` is only the one-time seed source: `CompanyProfiles/CompanyProfileSeeder` (after `EnsureDatabaseReadyAsync`) copies the `CompanyProfile` section (name, address, postal code, city, tax number, phone, email; `CompanyProfile__*` environment variables win) into the table when it has no row, failing fast on a missing field or a template marker while the table is empty. Once a row exists the configuration is ignored, so a deploy never overwrites an Admin's edits. Real company data never enters the repository.
- `GET`/`PUT /api/admin/company-profile` (`CompanyProfiles/CompanyProfileEndpoints.*`, `AdminOnly`, DTO-only `CompanyProfileDto`, CSRF like every unsafe `/api` call) read and replace the row. `CompanyProfileValidator` answers 400 keyed by camelCase field: all seven fields required (trimmed), `taxNumber` `^\d{8}-\d-\d{2}$`, `postalCode` `^\d{4}$`, phone and email validated and normalized by `Normalization/ContactNormalization` like the mechanic profile; caps live in `CompanyProfileLimits` (name 150, addressLine 150, city 50, phone 20, email 150).
- Company profile write-back (Development only): after `PUT /api/admin/company-profile` saves the row, `CompanyProfiles/CompanyProfileWriteBack` (behind `ICompanyProfileWriteBack`) rewrites the seven `ARSM_COMPANY_*` lines of the file at `CompanyProfile:WriteBack:EnvFilePath` (line-wise via `EnvFileRewriter`; a missing key goes to the end of the `# --- Company letterhead on quote PDFs ---` block, line endings kept) and the `CompanyProfile` values of the file at `CompanyProfile:WriteBack:LocalSettingsPath` (`LocalSettingsRewriter`, rest byte-identical). The AppHost sets both paths relative to its directory; an unset path or missing file is skipped (Information log), IO failures are a Warning, the request never fails, and Production writes nothing. The seed direction is unchanged: hand edits of these files never flow into the DB after the first start.
- `GET /api/quotes` also takes an optional `appointmentId` filter (`q.AppointmentId == appointmentId`) beside `vehicleId`; ordering, paging and the `QuoteListItemDto` shape are unchanged.
- The part number and labor code printed next to a line description come from the live catalog, not from the line snapshot: the snapshot keeps description, price and VAT rate only, so a hand-written or orphaned line prints a dash.

## Company Result Anchors

- `GET /api/company-results?year={int?}&month={int?}` (`Reporting/CompanyResultEndpoints.*`) under the `MechanicOnly` policy, the first aggregating endpoint in the project. It follows the AdminEndpoints pattern: hand-written LINQ projected straight into a DTO, no service layer.
- A quote belongs to the period its `CreatedAt` falls in, whatever its status is today, so the monthly figures add up to the yearly one and a past month never changes because an old quote was accepted now. The period is cut as a UTC range, the same way the monthly appointment query cuts one.
- `Sent` splits into two rows at query time from `ValidUntil >= now`: pending (still live) and expired. There is no stored Expired status, so the report ages with the calendar without a background job. `Draft` appears in no revenue row at all, only as a count.
- An empty period answers 200 with zeroed rows and a full month list, never 404, so the page has one rendering path. An out-of-range year or month is 400 `invalid_date_range`, matching the appointment month query.
- Totals come from the stored quote amounts; the VAT and parts/labor breakdowns come from the accepted quotes' stored line amounts. Nothing is recomputed in the report.

## Engineering and Size Rules

- Apply SOLID/OOP; use GoF patterns only when justified.
- Source > 500, tests > 250, class/service > 300: split required.
- Function/method target <= 60 lines where practical.

## Test and Validation Policy

- `http-endpoint-test` only for explicit request or significant API behavior change.
- `sql-database-test` only for explicit request or significant schema/persistence change.
- `e2e-playwright-test` only for explicit request or significant frontend flow change.
- Use `python scripts/run-local-test-suite.py http|sql|all` and review sanitized summary.
- Unit tests: `tests/AutoService.UnitTests` (xUnit, part of `app/AutoService.slnx`, so `dotnet test` in `app/` runs it in the pre-push backend stage and CI) covers the pricing calculators (`MoneyRounding`, `QuoteLineCalculator`, `QuoteTotalsCalculator`, `PricingCalculator`) and the ordering rule of `SessionRevocationService` through `InternalsVisibleTo`; add a unit test only for pure in-process logic, the HTTP and SQL suites stay the contract tests.
- Schema gate: `dotnet tool run dotnet-ef -- migrations has-pending-model-changes --project AutoService.ApiService` must pass; it runs offline (no database) and fails when entities changed without a matching migration. The EF CLI is pinned in `dotnet-tools.json`. `AutoServiceDbContextFactory` supplies the design-time context, so the gate never builds the application host and needs no secrets; CI runs it on every push.
