# Tests Rules

## Persona

- Primary owner: Zsombor
- Architecture escalation: Patrik

## Scope

- API suites: `tests/API/**/*.http`
- DB suites: `tests/Database/**/*.sql`
- Local test runner: `scripts/run-local-test-suite.py`

## Trigger Policy

- Heavy test work runs only on explicit user request, or when the agent-specific trigger applies:
  - HTTP: significant API endpoint/contract/auth/status/validation behavior change.
  - SQL: significant schema/migration/persistence/seed-data/integrity change.
  - E2E/Playwright: significant frontend structural/UI flow or user-visible journey change.
- Non-behavioral change: skip heavy test agents; run docs-sync only for test-layer docs.
- New feature + triggered test agent: auto-generate missing coverage before run/update.

## Engineering Quality in Tests

- Tests must be readable, deterministic, and maintainable.
- Keep setup explicit and assertions focused.
- Prefer smaller scenario-focused files over large all-in-one suites.
- Use `python scripts/run-local-test-suite.py [all|playwright|http|sql]` for local full-suite or selected-suite execution.
- Treat `tests/.artifacts/test-suite-summary.json` as the AI-readable sanitized test report; do not publish raw tool logs.

## Size Guardrails

- Preferred test file size <= 180 lines.
- Hard limit: > 250 lines must be split by scenario/responsibility.

## SQL Safety

- AI SQL user: `ai_agent_test_user`.
- Read-only `SELECT` only. No DML/DDL.

## Credentials & Secrets Policy (Mandatory)

Never hardcode credentials, passwords, connection strings, or host addresses in test files.

### Secret Files (gitignored — never commit)

| File | Scope | How consumed |
| --- | --- | --- |
| `.secrets` (repo root) | E2E / Playwright tests | Loaded by `python scripts/run-local-test-suite.py playwright` |
| `tests/.env` | HTTP API tests (`.http` files) | `{{$processEnv VAR}}` in REST Client / HTTP Client |
| `tests/.artifacts/` | Local sanitized test summaries | Generated by the Python test runner; gitignored |

Template: `tests/.env.example` (committed — values are placeholders only).

### Key Variable Names

- `ARSM_TEST_MECHANIC_EMAIL` / `ARSM_TEST_MECHANIC_PASSWORD` — non-admin mechanic login
- `ARSM_TEST_ADMIN_EMAIL` / `ARSM_TEST_ADMIN_PASSWORD` — admin mechanic login
- `ARSM_TEST_CUSTOMER_EMAIL` — passive customer (no login)
- `ARSM_TEST_PASSWORD` / `ARSM_TEST_WRONG_PASSWORD` — shared positive/negative passwords
- `ARSM_TEST_MECHANIC_NEW_PASSWORD` — used in password-change scenarios
- `AutoService_ApiService_HostAddress` — API base URL for `.http` files
- `ARSM_E2E_*` aliases — optional overrides for helper-based E2E suites when present

### Rules

- **HTTP tests**: use `{{$processEnv VAR_NAME}}`; never write literal email/password strings.
- **SQL tests**: read-only `SELECT`, no credentials embedded — connection via `ai_agent_test_user`.
- **E2E tests**: if a helper such as `e2e-env.ts` exists, use it for credential loading; otherwise use env vars directly and never inline credentials.
- **Running tests**: prefer the Python runner from the repo root; it loads local env files, sets non-secret `PORT=5173` for Playwright when absent, and writes a sanitized summary.
- If a required variable is absent: surface the name and point to `tests/.env.example` or `.secrets`.

## AI Test Runner Contract

- For full test investigations, run `python scripts/run-local-test-suite.py` rather than shell-specific suite commands.
- Inspect `tests/.artifacts/test-suite-summary.json` first; use its sanitized `status`, `details`, and `outputTail` to decide whether to add tests, fix stale tests, or investigate product behavior.
- Never paste raw `.env`, `.secrets`, local MCP config, connection strings, cookies, tokens, absolute local paths, or unsanitized command output into agent reports.

## Current Coverage Anchors

- HTTP and SQL coverage must track the vehicle VIN/kW/drivetrain contract and absence of HP/torque fields.
- HTTP coverage must track customer list/search vehicle plates plus email, exact license plate, and name lookup endpoints.
- Playwright coverage must track scheduler intake email/plate/name lookup and the customer details panel/split-view history flow.

## Hygiene

- Use environment-driven credentials and runtime-unique test data.
- Keep suites chunked and focused.
- Keep this file aligned with `.github/instructions/tests.instructions.md`.

## Trigger Gates

- `http-endpoint-test` runs only on explicit request or significant API endpoint/contract behavior change.
- `sql-database-test` runs only on explicit request or significant schema/persistence behavior change.
- `e2e-playwright-test` runs only on explicit request or significant frontend structural/UI flow change.
- If a new feature triggers these agents, generate missing coverage first.
- Non-behavioral changes default: docs-sync only for test-layer docs.
